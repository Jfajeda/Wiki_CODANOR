1. Resumen Ejecutivo

Visión general del proyecto Wiki CODANOR y su propósito estratégico.

¿Qué es?

Wiki CODANOR es un sistema RAG (Retrieval-Augmented Generation) local que centraliza el conocimiento generado por los 10 proyectos de consultoría de CODANOR. Permite realizar consultas en lenguaje natural sobre normativas, actas, plantillas y documentación técnica sin necesidad de enviar ningún dato a la nube.

¿Por qué?

El objetivo principal es reforzar las consultas de IA con documentos propios: normativas vigentes, políticas internas de clientes, actas de reunión y guías técnicas. Todo permanece en infraestructura local (NAS Synology + Mac), garantizando la máxima privacidad.

Beneficios clave

Privacidad total

Los datos de clientes nunca salen del hardware local. Sin APIs externas, sin telemetría.

Coste cero

Modelos open-source (Ollama), almacenamiento en NAS existente, sin suscripciones.

Funciona offline

Una vez configurado, el sistema opera sin conexión a Internet.

RGPD compliant

Cumplimiento normativo por diseño: datos personales procesados exclusivamente en local.

2. Objetivos del Proyecto

Metas concretas que persigue la implementación de la Wiki.

  1. Crear una base de conocimiento unificada alimentada por normativas (ENS, ISO 27001, LOPD-RGPD, NIS2), documentos de clientes y fuentes OSINT públicas.
  2. Vincular con las 10 plataformas existentes de CODANOR, permitiendo consultas cruzadas entre proyectos.
  3. Funcionar como Wiki-personal consultable mediante interfaz web (Open WebUI), accesible desde cualquier dispositivo en la red local.
  4. Integrar con OpenCode vía MCP (fase futura), conectando la base de conocimiento directamente con el entorno de desarrollo.
Nota
La integración MCP con OpenCode está planificada como Fase 4. El sistema es completamente funcional sin ella.

3. Arquitectura del Sistema

Diagrama de componentes y flujo de datos del sistema RAG local.

Diagrama de componentes

NAS Synology ⟶ Mac (Motor Inferencia + Vectores) ⟶ Open WebUI (Interfaz)

Almacenamiento    •    Procesamiento    •    Consulta

Componentes principales

  • Ollama — Motor LLM local que ejecuta los modelos de lenguaje.
  • nomic-embed-text — Modelo de embeddings para vectorizar documentos.
  • Open WebUI — Interfaz web con soporte RAG nativo y gestión de Knowledge Bases.
  • ChromaDB — Base de datos vectorial (integrada en Open WebUI).
  • Docker — Contenedores para aislar servicios.

Flujo de datos

Documentos (NAS) → Embeddings (nomic-embed-text) → Vectores (ChromaDB) → Consulta + LLM → Respuesta

6. Seguridad y RGPD

Medidas de protección de datos y cumplimiento normativo.

Separación PRIVADO / PÚBLICO

El NAS Synology mantiene dos áreas separadas físicamente en carpetas compartidas distintas. Los documentos con datos de clientes se almacenan exclusivamente en la zona PRIVADO, con permisos restringidos.

Principios de seguridad

  • Datos de clientes NUNCA salen del hardware — todo el procesamiento ocurre entre el NAS local y el Mac.
  • Vectores locales — ChromaDB se ejecuta dentro del contenedor Docker en el Mac. Los embeddings no se transmiten a ningún servicio externo.
  • Normativas públicas — opcionalmente pueden respaldarse en Google Drive como backup, ya que son documentos de acceso público.
  • Sin telemetría — ni Ollama ni Open WebUI envían datos de uso a terceros.
  • Sin APIs externas — el sistema no depende de OpenAI, Anthropic u otros proveedores cloud.
  • Sin cloud — toda la infraestructura es on-premise.
Datos de clientes
Bajo ninguna circunstancia se deben subir actas de reunión, logs de clientes o plantillas con datos personales a servicios en la nube. Esto incluye Google Drive, OneDrive y cualquier otro servicio de almacenamiento externo.

9. Plan de Implementación

Fases del despliegue, desde la preparación del NAS hasta la integración con OpenCode.

Fase 0 — Preparar NAS ~10 min

  1. Crear carpeta compartida wiki_codanor en el NAS Synology.
  2. Crear estructura de subcarpetas: PRIVADO/ y PUBLICO/ con las 10 colecciones.
  3. Montar la carpeta en el Mac: mount_smbfs.
# Crear punto de montaje y conectar
sudo mkdir -p /Volumes/wiki_codanor
mount_smbfs //usuario@IP_NAS/wiki_codanor /Volumes/wiki_codanor

Fase 1 — Instalar motor ~30 min

  1. Descargar el modelo de embeddings:
ollama pull nomic-embed-text
  1. Levantar Open WebUI con Docker Compose:
# docker-compose.yml
services:
  open-webui:
    image: ghcr.io/open-webui/open-webui:main
    ports:
      - "3000:8080"
    volumes:
      - open-webui:/app/backend/data
    extra_hosts:
      - "host.docker.internal:host-gateway"
    restart: unless-stopped

volumes:
  open-webui:
docker compose up -d
  1. Acceder a http://localhost:3000 y crear cuenta de administrador.

Fase 2 — Primera carga 1-2 horas

  1. En Open WebUI → Knowledge → crear las Knowledge Bases (una por colección).
  2. Subir documentos desde el NAS montado (drag & drop).
  3. Probar consultas: “¿Qué controles del ENS aplican a sistemas de categoría MEDIA?”
Consejo
Empezar con la colección ENS o LOPD-RGPD (menor volumen de documentos) para validar el flujo completo antes de cargar todas las colecciones.

Fase 3 — Automatización Futura

  • Scripts de ingestión automática desde NAS (ingest_nas.py).
  • Descarga periódica de fuentes OSINT (fetch_osint.py).
  • Vinculación bidireccional con herramientas de seguimiento de proyectos.

Fase 4 — Integración MCP Futura

  • Conectar la Wiki con OpenCode mediante protocolo MCP (Model Context Protocol).
  • Permitir a OpenCode consultar la base de conocimiento directamente desde el terminal.
  • Crear herramientas MCP personalizadas para cada colección.

11. Mantenimiento y Actualización

Procedimientos para mantener la base de conocimiento actualizada.

Añadir documentos

Desde Open WebUI, usar drag & drop para subir nuevos ficheros. Los documentos deben estar previamente almacenados en el NAS montado en /Volumes/wiki_codanor/.

Re-ingestión

Cuando un documento existente se modifica (ej. nueva versión de una plantilla), eliminar la versión anterior de la Knowledge Base y volver a subirla. Los vectores antiguos se reemplazan automáticamente.

Actualización OSINT

Ejecutar periódicamente el script de descarga:

python3 fetch_osint.py --output /Volumes/wiki_codanor/PUBLICO/OSINT/

Backup

El NAS Synology dispone de su propio sistema de backup (RAID + Hyper Backup). Los vectores en ChromaDB pueden respaldarse copiando el volumen Docker:

docker cp open-webui:/app/backend/data ./backup_open_webui_$(date +%Y%m%d)

Actualizar Open WebUI

docker compose pull && docker compose up -d
Antes de actualizar
Realizar siempre un backup del volumen Docker antes de actualizar Open WebUI a una nueva versión.
